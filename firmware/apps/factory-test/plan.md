# ファクトリーテスト計画

micro:bit v2.2 のハードウェアコンポーネントが正常に動作することを検証するファクトリーテスト。
ボタン操作（A/B）で各テストを順次実行し、LED表示で結果をフィードバックする。

---

## テストフロー

```
電源ON → LED全点灯テスト → ボタンA押下で次のテストへ進行
                            ボタンB押下で現在のテストを再実行

[1] LED テスト          (目視)
    ↓
[2] Speaker テスト      (聴覚)
    ↓
[3] Mic テスト          (自動 + LED可視化)
    ↓
[4] 加速度センサ テスト  (自動 + LED可視化)
    ↓
[5] 地磁気センサ テスト  (自動)
    ↓
[6] ボタン テスト        (操作)
    ↓
[7] タッチロゴ テスト    (操作)
    ↓
[8] 温度センサ テスト    (自動)
    ↓
[PASS] 全LED点滅 / [FAIL] エラー表示
```

---

## 各テスト詳細

### [1] LED テスト
| 項目 | 内容 |
|------|------|
| 目的 | 5x5 LED マトリクスの全画素が点灯すること |
| 手順 | 1. 全LED点灯 (1秒) → 2. 全LED消灯 (0.5秒) → 3. 1行ずつスキャン → 4. チェッカーパターン |
| 判定 | 自動: scan_tick動作確認 / 目視: 作業者がA(OK)またはB(NG)で判定 |
| PASS条件 | ボタンAが押された |
| FAIL条件 | ボタンBが押された |

### [2] Speaker テスト
| 項目 | 内容 |
|------|------|
| 目的 | スピーカーから音が出力されること |
| 手順 | 1. 1000Hz トーン再生 (0.5秒) → 2. 2700Hz (共振周波数) 再生 (0.5秒) → 3. 停止 |
| 判定 | 目視/聴覚: 作業者がA(OK)またはB(NG)で判定 |
| PASS条件 | ボタンAが押された |
| FAIL条件 | ボタンBが押された |

### [3] Mic テスト
| 項目 | 内容 |
|------|------|
| 目的 | マイクが音を検出できること |
| 手順 | 1. mic_enable → 2. 無音時のベースライン取得 (100ms, 16サンプル平均) → 3. Speaker 2700Hz再生 → 4. マイクADC値を取得 (100ms, 16サンプル平均) → 5. Speaker停止、mic_disable |
| 判定 | 自動: (再生時レベル - ベースライン) > 閾値 |
| PASS条件 | 差分 > 30 (ADC 10bit中) |
| FAIL条件 | 差分 ≤ 30 |
| 備考 | Speaker テストがFAILの場合はスキップ可能 |
| LED表示 | マイク入力レベルをリアルタイムでLEDバーグラフ表示 (左列=小, 右列=大)。作業者が声を出す/手を叩く等で反応を目視確認可能 |

### [4] 加速度センサ テスト
| 項目 | 内容 |
|------|------|
| 目的 | LSM303AGR が正常に応答し、妥当な値を返すこと |
| 手順 | 1. accel_init → 2. WHO_AM_I確認 (0x33) → 3. 加速度読み取り (10回平均) → 4. 静止状態で Z軸 ≈ 1000mg 確認 |
| 判定 | 自動 |
| PASS条件 | WHO_AM_I == 0x33 AND 800 < z_avg < 1200 AND abs(x_avg) < 300 AND abs(y_avg) < 300 |
| FAIL条件 | 上記を満たさない |
| 備考 | ボードが水平に置かれている前提 |
| LED表示 | 傾きをリアルタイム表示: 中央LEDを基準に、X/Y加速度に応じてドットが移動。ボードを傾けて反応を目視確認 |

### [5] 地磁気センサ テスト
| 項目 | 内容 |
|------|------|
| 目的 | LSM303AGR 地磁気計が正常に応答すること |
| 手順 | 1. mag_init → 2. WHO_AM_I確認 (0x40) → 3. 磁場読み取り → 4. ベクトル長が妥当な範囲か確認 |
| 判定 | 自動 |
| PASS条件 | WHO_AM_I == 0x40 AND 200 < magnitude < 800 (μT) |
| FAIL条件 | 上記を満たさない |

### [6] ボタン テスト
| 項目 | 内容 |
|------|------|
| 目的 | ボタンA/Bが正常に動作すること |
| 手順 | 1. LED表示 "A" → ボタンA押下待ち (5秒タイムアウト) → 2. LED表示 "B" → ボタンB押下待ち (5秒タイムアウト) |
| 判定 | 自動（入力検知） |
| PASS条件 | 両ボタンが押された |
| FAIL条件 | タイムアウト |

### [7] タッチロゴ テスト
| 項目 | 内容 |
|------|------|
| 目的 | フロント面タッチロゴが反応すること |
| 手順 | 1. LED表示 "T" → タッチ待ち (5秒タイムアウト) |
| 判定 | 自動（入力検知） |
| PASS条件 | タッチが検出された |
| FAIL条件 | タイムアウト |

### [8] 温度センサ テスト
| 項目 | 内容 |
|------|------|
| 目的 | nRF52内蔵温度センサが妥当な値を返すこと |
| 手順 | 1. 温度読み取り → 2. 妥当な範囲か確認 |
| 判定 | 自動 |
| PASS条件 | 10°C < temp < 50°C (室温想定) |
| FAIL条件 | 上記を満たさない |

## 結果表示

| 状態 | LED表示 |
|------|---------|
| テスト中 | 該当行のLEDが点滅 |
| PASS | 該当行の全LED点灯 |
| FAIL | 該当行の中央LED点滅 (高速) |
| 全PASS | 全LED点灯 → チェックマーク表示 |
| いずれかFAIL | ×マーク表示 |

行の対応:
- Row 0: 未使用 (ステータス表示)
- Row 1: LED テスト結果
- Row 2: Speaker テスト結果
- Row 3: Mic テスト結果
- Row 4: 加速度センサ テスト結果

## 実装方針

```cpp
// テスト関数のインターフェース
enum TestResult { TEST_PASS, TEST_FAIL, TEST_SKIP };

TestResult test_led(void);
TestResult test_speaker(void);
TestResult test_mic(void);
TestResult test_accelerometer(void);
TestResult test_magnetometer(void);
TestResult test_buttons(void);
TestResult test_touch(void);
TestResult test_temperature(void);
```

- 各テストは独立した関数として実装
- `usermain()` からシーケンシャルに呼び出し
- ボタン入力は polling (μT-Kernel タスクスリープ + GPIO読み取り)
- テスト間は ボタンA で遷移（自動進行モードも検討）
- Mic/加速度テストではセンサ値をLEDにリアルタイム表示し、
  一定時間後に自動判定 or ボタンAで判定確定

---

## 依存コンポーネント

- `led` - LED制御
- `speaker` - スピーカー制御
- `mic` - マイク制御
- `accelerometer` - 加速度センサ制御
- `magnetometer` - 地磁気センサ制御 (**新規作成必要**)
- `button` - ボタンA/B入力 (**新規作成必要**)
- `touch` - タッチロゴ入力 (**新規作成必要**)
- `temperature` - 温度センサ (**新規作成必要**)
- `osal` - タスクスリープ/タイマ (既存)
