# 位置推定アルゴリズム設計用シミュレータ計画

## 前提

- **入力**: 各アンカー（送信機）からの RSSI 値の時系列（波形取得は別担当が実施済み）
- **出力**: 受信機の推定位置座標 $(x, y)$
- **目的**: アルゴリズム選定・パラメータチューニング・精度評価をソフトウェア上で完結させる

## モジュール詳細

### モジュール 1: 環境モデル（Ground Truth 生成）

受信機の真の位置・軌跡と、アンカー配置を定義する。

| パラメータ | 説明 | 例 |
|-----------|------|-----|
| フィールド寸法 | 2D 空間の範囲 | 10m × 10m |
| アンカー座標 | 固定送信機の位置リスト | $(0,0), (10,0), (5,10), ...$ |
| 受信機軌跡 | 真の位置の時系列 | 直線移動 / ランダムウォーク / 固定点群 |
| サンプリングレート | 観測の時間間隔 | 100 ms（BLE 広告間隔相当） |

**軌跡パターン**:
- **静止点群**: 精度評価の基本。グリッド状に配置して全域の誤差分布を取得
- **直線移動**: 一定速度で移動。フィルタの追従性評価
- **ランダムウォーク**: 実際の人間の移動に近似した不規則移動
- **競技シナリオ軌跡**: TRON 競技の想定動線

### モジュール 2: 観測生成（RSSI シミュレータ）

真の位置からアンカーまでの距離を計算し、RSSI 観測値を生成する。

#### 基本モデル: Log-Distance Path-Loss + ノイズ

$$
RSSI_{\text{sim}}(d) = RSSI(d_0) - 10 \, n \, \log_{10}\!\left(\frac{d}{d_0}\right) + X_\sigma
$$

| パラメータ | 調整範囲 | 用途 |
|-----------|---------|------|
| $RSSI(d_0)$ | -40 〜 -60 dBm | 送信電力の模擬 |
| $n$ | 2.0 〜 4.0 | 環境の遮蔽度 |
| $\sigma$ | 2 〜 8 dB | ノイズ強度 |

#### 拡張ノイズモデル（段階的に追加）

| レベル | モデル | 説明 |
|--------|--------|------|
| Lv.1 | ガウスノイズのみ | $X_\sigma \sim \mathcal{N}(0, \sigma^2)$ |
| Lv.2 | + 時間相関 | 連続時刻の RSSI に AR(1) 相関を付与 |
| Lv.3 | + 外れ値 | 一定確率で大幅な異常値（マルチパス等の模擬） |
| Lv.4 | + アンカー個体差 | 各アンカーで $n$, $RSSI(d_0)$ が異なる |
| Lv.5 | + 遮蔽（NLOS） | 特定アンカーに対し追加損失を付与 |

#### 実測データ注入モード

シミュレータには**合成データ**と**実測データ**の両方を入力できるインターフェースを設ける：

```python
class RssiSource(Protocol):
    def get_observations(self, t: float) -> dict[str, float]:
        """時刻 t における各アンカーからの RSSI を返す"""
        ...
```

- `SyntheticSource`: 上記モデルで合成生成
- `RecordedSource`: 別担当が取得した実波形データ（CSV等）を読み込む

これにより、合成データで開発 → 実測データで検証、のワークフローが成立する。

### モジュール 3: 推定器（アルゴリズム本体）

プラグイン方式で複数の推定アルゴリズムを切り替え可能にする。

```python
class Estimator(Protocol):
    def initialize(self, anchors: dict[str, tuple[float, float]], params: dict) -> None: ...
    def update(self, rssi_obs: dict[str, float]) -> tuple[float, float]: ...
    def reset(self) -> None: ...
```

#### 実装候補（優先順）

| # | アルゴリズム | 概要 | 実装難度 |
|---|-------------|------|---------|
| 1 | 重み付き三辺測量 | RSSI→距離→最小二乗。ベースライン | 低 |
| 2 | EKF (拡張カルマンフィルタ) | 線形化した状態空間モデルで逐次推定 | 中 |
| 3 | 粒子フィルタ | 非線形・非ガウスに対応。地図制約も容易 | 中 |
| 4 | k-NN フィンガープリント | 事前 RSSI マップと照合 | 低（マップ作成は手間） |
| 5 | AoA + RSSI 融合 | 角度情報が使える場合の拡張 | 中〜高 |

### モジュール 4: 評価器

推定位置と真位置を比較し、定量的に精度を評価する。

#### 指標

| 指標 | 定義 |
|------|------|
| **平均誤差 (MAE)** | $\frac{1}{T}\sum_t \|\hat{\mathbf{p}}_t - \mathbf{p}_t\|$ |
| **RMSE** | $\sqrt{\frac{1}{T}\sum_t \|\hat{\mathbf{p}}_t - \mathbf{p}_t\|^2}$ |
| **95 パーセンタイル誤差** | 誤差分布の 95% 点 |
| **CDF プロット** | 誤差の累積分布関数 |
| **収束時間** | フィルタが初期収束するまでのステップ数 |

#### 可視化

- 2D トラジェクトリプロット（真位置 vs 推定位置）
- 誤差ヒートマップ（空間的な精度分布）
- 時系列誤差プロット
- パラメータ感度分析グラフ（$\sigma$ vs RMSE 等）

## 開発フェーズ

### Phase 1: 最小動作版（MVP）

**目標**: 最も単純な条件でパイプラインを通す

- 環境: 2D 正方形フィールド、アンカー 4 基（四隅）
- 観測: Lv.1 ノイズ（ガウスのみ）
- 推定: 重み付き三辺測量（ベースライン）
- 評価: MAE / RMSE / 軌跡プロット
- 受信機: 静止点で評価

**成果物**: 「ノイズ $\sigma$ を変えたときの測位精度」のグラフ

### Phase 2: フィルタ導入

**目標**: 時系列処理で精度改善を確認

- 推定: EKF / 粒子フィルタを追加実装
- 軌跡: 移動シナリオ（直線 / ランダムウォーク）
- 比較: フィルタなし vs KF vs 粒子フィルタの精度比較

**成果物**: 「手法別精度比較表」と「追従性の時系列プロット」

### Phase 3: ロバスト化

**目標**: 現実的なノイズ条件での動作確認

- 観測: Lv.2〜5 のノイズモデルを順次追加
- 推定: 外れ値除去ロジック、適応的パラメータ推定
- アンカー配置最適化: 配置パターンと精度の関係を調査

**成果物**: 「ノイズ条件別の推定器ロバスト性評価」

### Phase 4: 実測データ統合

**目標**: 合成データから実データへの移行

- `RecordedSource` に別担当の実測 RSSI データを投入
- 合成データで調整したパラメータが実データで有効か検証
- 必要に応じて path-loss パラメータの再校正

**成果物**: 「実測データでの位置推定精度レポート」

### Phase 5: 競技シナリオ最適化

**目標**: TRON 競技の条件に特化したチューニング

- 競技フィールドの寸法・アンカー配置を反映
- 競技ルールに基づく制約の組み込み
- リアルタイム性の確認（計算時間 < 観測間隔）

## 入出力インターフェース仕様（別担当との接続点）

別担当から受け取る RSSI データの想定フォーマット:

```csv
timestamp_ms,anchor_id,rssi_dbm
0,anchor_1,-45.2
0,anchor_2,-52.1
0,anchor_3,-61.8
100,anchor_1,-44.8
100,anchor_2,-53.5
100,anchor_3,-60.2
...
```

加えて、アンカー配置情報:

```csv
anchor_id,x_m,y_m
anchor_1,0.0,0.0
anchor_2,10.0,0.0
anchor_3,5.0,8.66
```

この 2 ファイルがあれば、シミュレータの `RecordedSource` に直接投入可能。

## リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| 合成ノイズモデルが実環境と乖離 | 実測で精度が大幅劣化 | Phase 4 で早期に実測データ検証。モデルを段階的に複雑化 |
| path-loss パラメータ不明 | 距離推定が不正確 | 校正データも別担当に依頼（既知距離での RSSI 計測） |
| アンカー数が不足 | 幾何学的に不定 | 粒子フィルタ + 移動モデルで補完。最低必要数を事前に特定 |
| 計算時間超過 | リアルタイム不可 | Phase 5 で計測。粒子数削減 or C拡張で対処 |
